# 代理组定时切换

在 LuCI 的 **服务 → Nikki → 代理组定时切换** 中添加规则。规则保存在
`/etc/config/nikki_schedule`，新规则默认停用，安装包不带示例启用规则。

1. 打开页面，从当前运行的 Mihomo API 自动读取完整 `Selector` 组名。
2. 添加规则，从下拉列表选择组名、时段内和时段外目标，不需要手工输入名称。名称按原样保存，支持 emoji、空格、引号等字符，不要根据截图缩写名称。
3. 输入每天的开始、结束时间（`HH:MM`），启用规则，保存并应用。
4. 修改保存后下一分钟检查；通常按所选 1、5、10、15、30、60 分钟间隔检查。页面显示路由器本地时间、最近检查时间、当前选择和错误状态。

例如，从 API 选择实际的油管 select 组，设置 `18:00` 至 `22:00`，时段内目标选
`🇺🇸-ai专用-dmit`，时段外目标选 `高质量节点-select`。这些仅是使用示例，必须以实际 API 名称为准。

## 时间与优先级

- 使用路由器本地时间和时区，不使用浏览器时区。请先保证路由器时间正确。
- 开始时间包含，结束时间不包含；`18:00–22:00` 在 18:00 使用时段内目标，22:00 恢复时段外目标。
- 开始时间晚于结束时间表示跨午夜，例如 `22:00–06:00`。
- 起止时间相同会拒绝保存，后台也不执行该规则。时段内、外选项相同允许，表示保持固定选择。
- 同组只能启用一条规则，界面拒绝重复启用；若手工修改 UCI 产生重复，该组的所有启用规则都跳过并报告冲突，避免来回切换。
- 停用或删除规则后不再管理该组，保留当前选择，不主动恢复某个出口。
- 每次都根据当前时间和实际 API 状态核对，不依赖上次切换记录。开机、核心重启、手工改选或时钟调整后，下次检查会重新恢复目标；API 暂时不可用时等下一分钟重试。
- 仅管理 `select`（API 类型 `Selector`）组；`url-test`、`fallback` 等自动组不能作为被管理组。目标可以是该 select 组已有的节点或子组。

## 流量影响

调度仅发送代理组选项的 `PUT` 请求，不重载核心、不关闭连接。旧连接可能继续使用原出口，直到应用重新建立连接。

规则独立于 `nikki` 主配置，因此保存规则不会触发主服务的重载或“重载后清除旧连接”行为。
如果同时有其他尚未应用的 LuCI 配置，标准“保存并应用”仍会应用这些其他改动。

如果上层“节点选择”或其他组引用了这个组，所有经过它的流量都可能受到影响，不能仅凭“油管”名称认为只影响 YouTube。

## API、调度与排查

- API 地址及认证读取 `/etc/nikki/run/config.yaml`，复用 Nikki 当前 Unix socket 或 HTTP/TLS 控制器配置，不创建监听端口。通配监听地址映射到本机回环地址；显式地址保持原绑定地址。TLS 沿用项目现有本地 API 的自签名证书处理方式。配置 Unix socket 时优先使用它；否则优先 HTTP，其次 TLS。
- 认证通过自动删除的临时文件描述符交给 curl，不写入命名文件、不放到命令行、不返回浏览器。请求有连接和总时限，不跟随重定向、不使用环境 HTTP 代理。
- 请求按 [Mihomo 代理 API](https://wiki.metacubex.one/api/#proxiesproxies_name) 获取组及选项，只在当前选项不同且两个目标仍属于该组时切换。组名进行 UTF-8 百分号编码，请求正文使用 JSON 序列化。
- 主服务成功启动后创建一条每分钟的 `#nikki proxy schedule` cron 任务；启动会先清理旧 `#nikki` 行，再统一重建。停止/重载会清理它，重载完成后重新创建。启动回调还强制发起一次检查；API 未就绪则下一分钟重试。cron 始终每分钟唤醒，worker 按配置间隔跳过非整点分钟，因此改变间隔不需要重载主服务。
- 检查用 `flock` 防重入。停止/重载先撤销 started 标记并等待正在执行的检查结束；锁文件在同一次开机内不删除，避免锁 inode 竞争。规则较多且 API 持续超时时，一轮可能超过一分钟，重叠轮次跳过。
- 状态保存在 RAM 中的 `/var/run/nikki/proxy_schedule.json`，不会每分钟写 UCI/闪存；停止时清理状态。超过配置检查周期加 90 秒未更新时界面显示等待检查，可查看 cron。日志在 Nikki 插件日志中，以 `Schedule` 标记；只记录实际切换和错误状态变化，不逐分钟刷相同错误。
- API 离线时保留已经保存的选项；恢复 API 后重新载入页面获取完整列表。订阅更新删掉组或选项后，状态会提示无效，不自行选择其他节点。

安装路径包括正常 OpenWrt 软件包和 `install-luci-patch.sh`。重复应用补丁保留已有规则文件；运行中的 Nikki 安装补丁时补上分钟任务，不需要为调度主动重启核心。此仓库修改本身不会自动安装到路由器。

## 本地测试

```sh
# The ucode tests require a native interpreter with the fs module.
UCODE=/path/to/ucode python3 -m unittest discover -s tests -v
node --test tests/*.test.mjs
sh -n nikki/files/nikki.init
sh -n install-luci-patch.sh
```

运行前请安装 ucode 或设置 `UCODE`，`UCODE_LIB` 可指定其模块目录。
测试覆盖时间边界、跨午夜、相同起止时间拒绝、停用、同组冲突、重启恢复、API 故障重试、Unicode 和特殊字符转义、认证参数隔离、锁竞争、状态落盘和 cron 重建/清理。

浏览器可使用真实 LuCI 静态资源配 mock RPC/UCI 验证表单；它不能替代目标 OpenWrt 上 rpcd/ubus/procd、BusyBox cron 和实际 Mihomo 的集成验证。Mac 本地源码检查不等于 OpenWrt SDK 编译成功。
